# Experiment: kanalgebundene Kamera-Statusabfrage

Dieser interne Android-WIP ergänzt eine ausdrücklich aufzurufende, rein lesende Abfrage. Sie ist weder im Dashboard noch in der Benutzeroberfläche angeschlossen. Eine Antwort wird nur für die ausstehende UUID-Anfrage, den gleichen freigegebenen LAN-Kanal, eine monotone Antwortrevision und innerhalb von fünf Sekunden akzeptiert. Bei Verbindungsende werden ausstehende und empfangene Daten verworfen. Die Kameraseite liest Aufnahmephase, Aufnahme-ID, gegebenenfalls Projektzuordnung und Kameraseite gemeinsam unter dem vorhandenen Aufnahme-Lock; sie ändert dabei weder Aufnahme noch Kamera. Die Projektzuordnung gilt nur für einen innerhalb dieser LiveSession angenommenen Start. Ein unbekannter Projektbezug wird ausdrücklich als unbekannt gemeldet.

Die Antwort ist eine kurzlebige Momentaufnahme und kann unmittelbar danach veralten. Sie ist keine Autorisierung für einen Aufnahmebefehl. Der bestehende LAN-Kanal authentifiziert seine Sitzung, beweist aber noch keine dauerhafte, serverseitig verifizierbare Kameraidentität und verschlüsselt den Nachrichteninhalt nicht. Keine Skripte, Zugangsdaten, Bild- oder Toninhalte werden hier übertragen. Eine tatsächliche Webintegration benötigt insbesondere überprüfbare Geräte- und Sitzungskopplung, Widerruf-/Logout-Fencing, Projektbindung bis zur Ausführung, sichere Transportvertraulichkeit sowie Ende-zu-Ende-Tests. Die neue Abfrage stellt diese Eigenschaften nicht bereit.

Die Unit-Fixture deckt Kanal-/Anfragebindung, Replays, TTL, monotonen Versionsstand, konkurrierende Rücksetzung und die verspätete Rücknahme eines früheren Requests ab. Sie ersetzt keine Instrumentierungs-, Netzwerk- oder Smartphone-Tests. Der Baustein basiert auf dem noch separaten LAN-Control-WIP und muss vor Zusammenführung gegen dessen integrierten Stand erneut geprüft werden.
